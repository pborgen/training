PFA Training · System Architecture

Coach,
schedule,
and ask.

A fitness-coaching platform: admins schedule workouts and manage clients; clients log sessions, check readiness, and chat with an AI exercise coach. One React SPA, one FastAPI backend, two standalone Python apps, on Terraform-managed AWS.

React 19 · TanStack · Vite FastAPI · asyncpg · raw SQL PostgreSQL · pgvector LangChain agents AWS App Runner · RDS · Bedrock

Two AI coaches

The most important distinction in the codebase: there are two separate AI coaches. One lives inside FastAPI; the other is a standalone agents app.

RAG coach

Runs inside FastAPI. retrieval.py does vector search over knowledge_documents; generation.py calls Claude on AWS Bedrock via AnthropicBedrock. Exposed by the rag router.

in-process · grounded

LangChain agents

Separate uv app. Provider chosen in models.json (Anthropic · Groq · Ollama). The coach ReAct agent reads real app data by calling /api/* with dev-auth headers; the team supervisor routes each turn to one of four specialists.

out-of-process · tool-using
03

Backend routers

One file per feature under routers/, each an APIRouter registered in main.py. Auth via dependencies in auth.py — require_user / require_admin / require_coach.

RouterResponsibility
authLogin, identity, role resolution
profileClient profile read / write
adminAdmin-only user & content management (/api/admin/*)
coachesCoach spotlights & coach-facing routes (require_coach)
teamMulti-agent coaching team chat (/api/coach/team/chat)
exercisesExercise catalog (seeded)
routinesWorkout routines (JSONB exercise arrays)
scheduleScheduling workouts for clients
readinessDaily readiness check-ins
workout_logLogged workout sets / results
ragRAG exercise-coach Q&A endpoint

All schema lives in ensure_tables() (db.py); migrations are ALTER TABLE … ADD COLUMN IF NOT EXISTS. Seeds run from the lifespan and only insert when a table is empty. Raw SQL via asyncpg, no ORM; email is the primary user identifier throughout.

04

Deployment · AWS

A single container image (root Dockerfile) builds the SPA and serves it from FastAPI on App Runner. Private RDS and Bedrock are reached over a VPC connector. The agents and scraper are dev/ops tools — not part of the deployed service.

Image lives in ECR with a lifecycle policy; pushing a new tag triggers an App Runner redeploy automatically.

Private egress

App Runner reaches private RDS Postgres 16 and a bedrock-runtime VPC endpoint through a VPC connector. POSTGRES_URL comes from Secrets Manager.

05

Dev workflow

./scripts/dev.sh checks Postgres, runs FastAPI on :8080, and starts Vite (proxying /api → :8080). With ALLOW_DEV_AUTH_HEADERS=true the admin / client / coach dev accounts are seeded and the x-user-email header is accepted.

apps/api

uv run api — FastAPI + built client. uv sync to install deps.

apps/agent

uv run chatbot — LangChain agents. Provider set in models.json.
